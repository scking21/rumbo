# October 29 logo candidate

This source candidate builds on main `9de51cf2729c965aeaeee77abecc0c189b6e8873`. It adds the Rumbo logo described in [the brand notes](brand/README.md). It does not change behavior, protocol versions, stored data or tools. The only dependency change is in the Sites development tooling: `undici` is pinned to the patched 7.30.1 (under miniflare) and 8.12.2 (under jsdom), because new advisories against earlier versions fail the Sites `npm audit` gate.

## Prepared distribution identities

- Python engine/package **0.3.5** includes the local acceptance board with the wordmark in its header; its Python runtime and package metadata agree.
- OpenAI portable and Codex local adapters **0.3.6** bundle engine 0.3.5 and its board, with the new listing icon and brand color `#C42A78`. Both plugin manifests agree.
- Isolated Sites candidate **0.1.2** includes the hosted board with the same header. Its package, lock root and MCP server identity agree.
- Both acceptance-board MCP Apps `appInfo` identities are **0.1.2**. The MCP Apps protocol date and MCP server protocol negotiation are unchanged.
- The Claude adapter **0.3.6** carries the new listing icon at `rumbo/.claude-plugin/icon.svg`. Its scripts, hooks and skills are unchanged; the new version lets installed copies pick up the icon.

These patch identities distinguish changed package bytes from the merged engine 0.3.4 / OpenAI 0.3.5 / Claude 0.3.5 / Sites 0.1.1 identities, following [the prior update](UPDATE-2026-10-18.md).

## What changed

- `rumbo/.claude-plugin/icon.svg` and `openai-plugin/rumbo/assets/icon.svg` hold the `r···o` symbol in place of the compass rose. Paths and manifest fields are unchanged.
- The OpenAI listing `brandColor` changes from `#237A4B` to `#C42A78`: 5.3:1 contrast on white and 3.0:1 on `#212121`.
- Both boards show the wordmark as inline SVG in place of the italic text brand. The letters use the text color and the fix uses `--owner`, so both board themes apply. It is labeled `rumbo` for assistive technology. The board keeps `img-src 'none'`; inline SVG needs no image source.
- `docs/brand/` holds the logo files and `make_logo.py`, which draws them.
