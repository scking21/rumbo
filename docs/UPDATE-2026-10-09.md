# Versioned update and rollback

## Candidate components

- Claude adapter 0.3.3 gives the fixes already merged in PR #8 a new cache identity. It bounds Stop retries when marker storage fails, handles malformed reason markers and prevents concurrent initialization from replacing an existing record. The adapter remains standalone Python 3.9+ standard-library code.
- Python engine 0.3.1 rejects incomplete HTTP bodies before dispatch and treats overflowing OAuth numeric dates as invalid. It includes the prior SQLite-backup lock fix and HTTP backlog correction. No ledger or registry format changes are introduced.
- OpenAI local adapter 0.3.2 bundles engine 0.3.1 and the updated board. Clipboard completion cannot change a newer detail panel, and rebuilding task lists preserves task focus. The portable and Codex manifests use the same adapter version. These versions are independent of the Claude adapter.

These are prepared distribution identities, not evidence of public release, marketplace approval or installed-host verification. The Sites changes are source-only until separately authorized deployment. Dependency pins are unchanged.

## Claude update path

Source changes on GitHub do not update an installed cache by themselves. After this candidate is reviewed and an authorized release reaches the marketplace branch, refresh the marketplace, update the installed plugin and reload it in Claude Code:

```sh
claude plugin marketplace update rumbo
claude plugin update rumbo@rumbo
claude plugin list
```

Use the existing installation scope if it differs from the CLI default. In an open session run `/reload-plugins`, or start a new session. Verify the active Rumbo manifest reports 0.3.3 and that its hook paths resolve inside that installed plugin directory. A local source test is not proof of that host state.

Do not uninstall the marketplace or delete caches to force an update. Preserve `.rumbo/record.json`, `.rumbo/verified-quotes.json` and existing marker state. See [Claude's install/update documentation](https://code.claude.com/docs/en/discover-plugins) and [marketplace maintenance documentation](https://code.claude.com/docs/en/plugins/host-marketplace).

## OpenAI local package and bindings

```sh
python3 scripts/package_release.py --kind local --output dist/rumbo-openai-0.3.2-local-plugin.zip
python3 scripts/package_release.py --kind source --output dist/rumbo-0.3.1-source.zip
python3 scripts/verify_installed_wheel.py
```

The local ZIP contains its runtime, so `scripts/run_mcp.py` must import the bundled `rumbo` package rather than a checkout or globally installed wheel. The host must supply the existing absolute private `PLUGIN_DATA` directory. The process starts unbound and connects only to an owner-provisioned alias. Keep the registry and project state unchanged. Replacing the plugin starts a new worker identity; it does not resume an old task lease. Never change the launcher to obtain reviewer or human authority.

## Verification and publication gates

Run Python tests, the preserved Claude adapter tests, installed-wheel verification, Sites tests/build/validation, compilation and whitespace checks on the exact candidate. Browser and Docker execution must be reported separately when unavailable locally. CI has real-browser and isolated synthetic deployment checks; it does not publish the candidate. Native independent review and actual Claude review are separate gates.

A draft GitHub PR is a review submission only. Merging, releasing, deploying, installing on an owner's computer and submitting to a marketplace are distinct actions with their own authorization and verification.

## Rollback

Preserve the previous installed package and its exact source revision before a separately authorized installation. If a regression appears, stop that plugin process and restore the prior verified package through the host's supported installation flow. Reload the host and verify the active manifest and hook/import paths. Do not edit private plugin settings, overwrite an unknown registry or copy another process's lease identity.

No data migration is part of this update, so rollback must preserve existing project state. The source baseline is `df30cf9213a30690bf3ec6431ec03fbc97909937`; the inherited four-fix candidate is `2f525dc022133103a723e1a29d595ff134db31c3`. Reverting distribution bytes does not undo user decisions or artifacts created afterward. Do not restore old database backups to roll back executable code.
