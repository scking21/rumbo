# November 24 Claude adapter 0.3.11

This builds on main `a90d9f3eab2b02e4f57f17f61924cd9ddd6ff31d`. It changes only the Claude adapter in `rumbo/`. The record format, the check kinds and the hooks it registers are unchanged.

## Distribution identities

- The Claude adapter is **0.3.11**.
- The Python engine/package **0.3.5**, the OpenAI portable and Codex local adapters **0.3.7** and the Sites candidate **0.1.3** are unchanged.
- The Codex local package (`--kind local`) bundles `rumbo/scripts/record.py` as its commitments runtime. A package built from this commit therefore carries two of these changes under the unchanged 0.3.7: the `show` header asks for the user's terms, and a named budget line gets the new refusal. Its other `init`, `validate`, `check` and `show` output is unchanged, and it never runs the Stop gate. Give the OpenAI adapters a new version before distributing a package built from here.

## What changed

- **The Stop gate reads the reply.** Claude Code passes the reply the user is about to read as `last_assistant_message`. A failing or unsourced check that this reply already states is no longer a problem for that stop. A conflict is stated when one line names what conflicts, read the way the source check reads the user's words: the time the plan reaches and the end it misses, or the minutes over ("five minutes past the close"); both dates and a word that orders them, with their years when they differ; or the total and its cap, or the excess ("$30 over the budget"). An assumed value is stated when a line names it and that line asks about it, or its section or the reply's opening calls values the agent's assumptions or estimates. When every problem is stated, the stop passes without using one of the session's three blocks; otherwise the block lists only what the reply left out. Before, the gate blocked whatever the reply said, so the agent repeated what it had just explained, and a later conflict could find the session's blocks used up. This is word matching, not understanding, and it reads at most the reply's first 20,000 characters. A host that sends no `last_assistant_message` gets the full block, as before.
- **Open problems are named in the user's terms.** The short repeat block now names each check with its label, and it, the `show` header and the skill ask for the status in the user's terms rather than the record's ids. In live sessions on 0.3.10 the agent wrote lines such as "Still open: C5, ..." to a user who never sees the record.
- **Settled assumptions.** The skill now says that when the user later gives a value the agent assumed, or their own plan replaces the one a check was about, recording their words and changing the check to their values is the user's correction, not changing a value to pass. In a live session on 0.3.10 the agent reported its own early budget split as an open assumption in 12 replies, the last four after it had told the user that their figures replaced it.
- **A named budget line gets a usable refusal.** An agent that writes an amount as `{"label": ..., "amount": N}` is told to use the plain number and name the lines in the check's label. Before, the refusal asked for `{"unit": N, "quantity": N}`, which is only for a price per unit. The record format is unchanged.
- **Long transcripts stay fast.** The gate bounds every transcript line's JSON nesting before decoding it. That check walked each character in Python and took about 95% of the gate's time: 4.1 s for a 60 MB transcript, against the hook's 10 s timeout, and a Stop hook that times out lets the turn end unchecked. It now uses string operations and one regular expression and accepts and refuses exactly the same inputs; 60 MB takes 0.74 s.

## Live sessions

Each session sent the paragraphs of a bundled eval prompt (`01-workshop-full` or `02-launch-full`) as 15 separate turns to Claude Code 2.1.331 with sonnet, using `claude -p --resume`. The bundled graders were then run on each session's `plan.md`, with haiku as the judge and the majority of three votes.

| | main (0.3.10) | first draft of the reader | this release, before the proposal words |
| --- | --- | --- | --- |
| Sessions | 3 | 3 | 4 |
| Stop blocks | 9: each session's limit of 3 | 8 | 5 |
| Turns whose reply named a record id such as "C5" to the user | 19 of 45 | 0 of 45 | 0 of 60 |
| Grader checks passed | 18 of 18 | 18 of 18 | 24 of 24 |

- On main, replaying the 9 blocked replies through this release's reader, 8 would have passed: each had already stated the problem, for example "a 9:45 start conflicts with your schedule by five minutes". Every session met a later conflict after its three blocks were used: the printer deadline after the workshop, or 100 flyers over the budget.
- The first draft required each value and its assumption word on one line and the total beside its cap. Most of its 8 blocks were on replies that disclosed the problem in forms it could not read: estimates in a table under a heading such as "Draft budget (my estimates)", or "They're $30 over the budget". This release reads those forms.
- Of the 5 blocks in the last arm, one was the unchanged no-record nudge, one the unchanged rule for deleted checks (the agent removed two checks that the user's speaker decision had made moot, then restored them), and three were on budget figures the agent called "my proposals". The proposal words added after that run let two of the three replies through; the third did not name the figures.
- These are small samples on synthetic prompts. Costs varied more between sessions than between arms, so no cost difference is claimed.
